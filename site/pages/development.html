Run from source

npm install
npm test

Chromium: chrome://extensions → Developer mode → Load unpacked → the extension/ folder.

Firefox / Zen:

npm run dev:firefox   # web-ext run with a fresh Firefox profile
npm run dev:zen       # same, in Zen Browser

Or build once with npm run build and load dist/firefox/manifest.json from about:debugging#/runtime/this-firefox → Load Temporary Add-on. npm run lint:firefox runs Mozilla's linter on the Firefox build.

Signing for Firefox (your AMO account)

Release Firefox only installs signed add-ons. ChroMind is signed as an unlisted add-on from your addons.mozilla.org developer account: Mozilla signs it, but it's offered only from this site, not the add-ons store. Same setup as YTMQ.

  1. Create API credentials on your AMO developer profile: addons.mozilla.org/developers/addon/api/key. You get a JWT issuer and a JWT secret.
  2. Add them as GitHub secrets on the repository: 
    gh secret set AMO_JWT_ISSUER -R T3lluz/ChroMind
gh secret set AMO_JWT_SECRET -R T3lluz/ChroMind
  3. Turn on GitHub Pages with Source: GitHub Actions (Settings → Pages). Every push to main runs .github/workflows/pages.yml: tests, packages, signs the Firefox build and deploys this site with the downloads and Firefox's update manifest.

The add-on id is chromind@t3lluz.com. The first signed upload creates the add-on on your account; later ones add versions. Mozilla takes each version number once, so ship a Firefox update by bumping the version: 

npm run release -- patch    # or minor, major, 1.2.3
git commit -am "Release v0.1.1" && git push

If the version is already on AMO, the workflow downloads that signed build instead of uploading again. Installed copies pick up new versions through update_url (https://t3lluz.github.io/ChroMind/chromind-firefox-updates.json).

Sign locally instead:

npm run pack
AMO_JWT_ISSUER=user:123:456 AMO_JWT_SECRET=… npm run sign:firefox

Hosting the site elsewhere (say t3lluz.com/chromind)? Set CHROMIND_SITE when packing so the Firefox update_url points there.

Docs and screenshots

npm run dev:site      # http://localhost:4173/ChroMind/
npm run screenshots   # Playwright: loads the extension, refreshes site/assets/screens

Docs pages are plain HTML in site/pages/ with a short front-matter comment for title, group and order.

Adding a provider

  1. Describe it in PROVIDERS and add a branch to runChat() and testProvider() in lib/providers/index.js.
  2. Add defaults in lib/settings.js and fields in options/options.js.
  3. If it's a CLI, add it to the Bridge instead: a provider/model prefix, a spawn branch and a stream parser.
